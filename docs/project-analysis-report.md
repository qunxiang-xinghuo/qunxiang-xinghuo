## 一、项目概述

**群像·星火 (Qunxiang Xinghuo)** 是一个基于真实职业经验的多人协同创作平台。核心理念：让不同职业背景的普通人，被扔进同一个冲突情境，用各自的职业本能碰撞出火花，共同完成一部一个人永远写不出的故事。

**技术栈**: Next.js 16 + React 19 + Prisma 7 + SQLite + Socket.io + DeepSeek AI
**测试覆盖**: 217+ 测试用例，Vitest + React Testing Library
**部署方式**: Docker + PM2

## 五、技术实现亮点

### 5.1 并发安全的匹配引擎

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  问题: SQLite 单写者，交互式事务的读快照在 BEGIN 时固定                        │
│  两个同时到达的请求会互相看不到对方的 waiting 记录，导致双双进入等待死锁        │
└─────────────────────────────────────────────────────────────────────────────┘

    解决方案: 进程级队列序列化

    Request A ──┐
                ├──▶ Promise 链 ──▶ 串行执行 ──▶ 数据库
    Request B ──┘

    代码实现:
    ┌─────────────────────────────────────────────────────────────────────┐
    │  let matchQueue = Promise.resolve();                                │
    │                                                                     │
    │  export async function findMatch(userId, criteria) {                │
    │    return new Promise((resolve, reject) => {                        │
    │      matchQueue = matchQueue.then(async () => {                     │
    │        try {                                                        │
    │          const result = await _findMatch(userId, criteria);         │
    │          resolve(result);                                           │
    │        } catch (e) { reject(e); }                                   │
    │      }).catch(() => {});                                            │
    │    });                                                              │
    │  }                                                                  │
    └─────────────────────────────────────────────────────────────────────┘
```

### 5.3 疗愈系统加密

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  疗愈会话加密方案                                                            │
└─────────────────────────────────────────────────────────────────────────────┘

    算法: AES-256-GCM
    密钥: 环境变量 HEALING_ENCRYPTION_KEY → SHA256 → 32字节

    加密流程:
    ┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
    │ 明文     │────▶│ 随机IV   │────▶│ AES加密  │────▶│ base64   │
    │ "你好"   │     │ 16字节   │     │ +AuthTag │     │ 输出     │
    └──────────┘     └──────────┘     └──────────┘     └──────────┘

    存储格式: base64(iv + authTag + ciphertext)
    · iv: 16字节随机初始化向量
    · authTag: 16字节认证标签 (防篡改)
    · ciphertext: 加密后的密文

    解密流程:
    ┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
    │ base64   │────▶│ 拆分     │────▶│ AES解密  │────▶│ 明文     │
    │ 输入     │     │ iv/tag/  │     │ 验证Tag  │     │ 输出     │
    └──────────┘     │ cipher   │     └──────────┘     └──────────┘
                     └──────────┘
```

## 十三、总结

### 项目定位
群像·星火是一个**基于职业身份的即兴创作平台**，核心价值在于：
1. **低门槛创作**: 选择身份即可开始，无需写作能力
2. **有意义的社交**: 基于职业视角的思想碰撞
3. **内容可沉淀**: 对白→火花→故事，创作成果可积累
4. **AI 辅助催化**: DeepSeek 驱动的智能引导，降低创作难度

### 技术特色
1. **TDD 驱动**: 217+ 测试用例，全链路覆盖
2. **并发安全**: Promise 链式队列解决 SQLite 并发问题
3. **三级降级**: AI 服务降级策略，保证可用性
4. **实时协作**: Socket.io 房间广播 + 导演控场
5. **内容安全**: AES-256-GCM 加密 + HMAC-SHA256 签名

### 商业模式
```
内容生产 (用户创作) → 内容分发 (知乎圈子) → 内容变现 (盐选分成)
     ↑                                              │
     └──────────── 创作者激励 (收益系统) ←──────────┘
```

### 目标用户
- **剧本杀爱好者**: 寻找低门槛的角色扮演体验
- **AIGC创作者**: 有表达欲，需要创作工具
- **职业人士**: 希望分享职业经验，理解其他行业
- **社交疲惫者**: 渴望有深度的思想碰撞
